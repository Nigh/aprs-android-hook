# 批量轨迹地图的数据与性能

选定日期、上报 ID 和设备范围后，首次 `/api/tracks?...&map=1` 查询一次该范围内的定位数据，返回分页列表、全部轨迹的轻量列表元数据，以及全部可绘制轨迹的 `{key, page, coordinates}`。列表仍每页只渲染 50 行；换页从已加载的元数据切片，不再重新查询数据库。地图仅把坐标转换成共享 MapLibre GeoJSON source 中的 LineString，使用两个共享图层显示细线和扩大点击区域。

选中轨迹通过 `/api/tracks/{key}` 单独读取完整点和测量值。该查询解码轨迹键，按上报 ID、设备、session 和日期范围查询，可使用 points 表现有的复合唯一索引；切换选择无需重新分组整个范围。地图中只有选中轨迹另用一份 source 绘制粗线、白色定位点和最多两个起终点 DOM 标记。地图路径带有其列表页码，所以跨页点击会切换列表页并高亮该行。

1000 条轨迹、30000 个点的合成数据中，完整点详情的紧凑 JSON 约 9.13 MB；仅坐标和轨迹索引的地图数据约 4.77 MB。这是原始序列化体积估算，不代表实际传输或 JS/GPU 内存峰值。当前实现避免批量传输重复的设备、session、时间和测量字段，也避免了 2000 个起终点 DOM 标记。只有一个点的轨迹没有可绘制线段，但仍能从列表选中并查看详情。

`BenchmarkTrackMap1000x30` 在本机 Intel Core Ultra 7 265K、SQLite 本地临时库中完成 3 次批量响应，平均约 90 ms/op，约 40.6 MB 分配/op。这包括范围查询、分组、距离计算、地图坐标与 JSON 响应构造；不包含网络、底图和浏览器绘制。浏览器使用合成轨迹在无头 Chrome 中验证了 1000 条线、30000 个坐标、跨页地图选择和列表选择。首次地图可见约 3 秒，包含开发服务器启动、WebGL 初始化和外部底图，不能当作生产环境承诺。

实际手机的首次加载时间、地图拖动帧率和内存仍取决于设备、底图网络、轨迹重叠程度和坐标精度；若出现瓶颈，应先实测，再考虑按缩放级别隐藏细节或抽稀。MapLibre 的 [大 GeoJSON 性能指南](https://maplibre.org/maplibre-gl-js/docs/guides/large-data/) 也建议减少字段与精度、复用简单图层并按缩放级别控制显示。
